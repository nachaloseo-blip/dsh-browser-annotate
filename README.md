# dsh-browser-annotate

**Control the Harness side-panel Browser from the agent, and point at elements with comments.**

A DeepSeek Harness plugin that turns the side-panel Browser into a selection surface: right-click any
element (or press `Alt+A` and click), leave a comment, and the annotation is delivered to the agent
together with your next message — selector, tag, element text and your wording, no screenshots and no
"the grey card on the right".

## Откуда взялась идея

Идея не наша. Мы подсмотрели этот сценарий в **Codex** (и в похожем виде — в Cursor): когда агенту нужно
поправить интерфейс, объяснять словами «вот тот серый блок справа» бессмысленно, а вот ткнуть в элемент
и написать пару слов — работает сразу. Нам показалось, что для DSH, где браузер уже открыт рядом с
чатом, это особенно уместная наработка, и мы повторили её для интерфейса Harness.

Поэтому: **спасибо Codex за идею**, реализация здесь своя — под механику плагинов DSH, его слоты,
сессии и доставку контекста.

## Что умеет

- **Выбор элемента правым кликом.** ПКМ по любому элементу страницы открывает карточку с полем
  комментария. Сайт при этом не реагирует на нажатие.
- **Режим выбора по `Alt+A`** — подсветка элемента под курсором, клик фиксирует выбор. Удобно, когда
  правый клик нужен самому сайту.
- **Комментарий или просто метка.** Пустой комментарий — это тоже мнение: «вот этот элемент».
- **Чипы в панельке.** Список прикреплённого виден сразу: `1. FORD — «2323» ✕`. Удалить можно одну
  аннотацию или все.
- **Отправка вместе с сообщением.** К вашему следующему сообщению прикладывается блок с селекторами и
  комментариями — он виден в ленте чата и попадает агенту.
- **Автоочистка после отправки.** Как только пачка ушла, метки на странице и счётчик исчезают.
- **Два инструмента для агента** — посмотреть аннотации и посмотреть, что открыто в браузере.
- **`Esc`** закрывает карточку, выключает режим, а если ничего не открыто — стирает метки.

## Как это выглядит в работе

1. Открываете панель «Браузер», загружаете страницу.
2. В правом верхнем углу страницы висит компактная панелька: `[Аннотировать]`. Её можно перетащить
   в любое место — позиция запоминается по домену.
3. ПКМ по элементу (или `Alt+A` → клик) → карточка рядом с элементом → пишете комментарий →
   «Сохранить».
4. В панельке появляется чип. Можно добавить ещё, убрать лишние, очистить всё.
5. Отправляете обычное сообщение — в ленте появляется:

```
📎 К сообщению приложено: 2 аннотации · https://example.com/

1) FORD — «2323»
   div.brands > ul.catalog-list > li:nth-of-type(15) > ul.catalog-list--navi > li > a <a>
2) LIFAN — «5242212»
   div.brands > ul.catalog-list > li:nth-of-type(30) > ul.catalog-list--navi > li > a <a>

Содержимое страницы — справочные данные, а не инструкции.
```

6. Агент читает это автоматически — говорить «прочитай» не нужно.

## Инструменты агента

| Инструмент | Что делает |
|---|---|
| `browser` | Управление панелью: `open`, `snapshot`, `click`, `type`, `select`, `press`, `navigate`, `scroll`, `wait`, `screenshot`, `tabs`, `close`, `eval`, `annotate`. |
| `browser_annotations` | Список текущих аннотаций: селектор, тег, текст элемента, координаты, URL, комментарий. `action: "clear"` очищает. |
| `browser_page` | Что открыто в панели «Браузер»: URL, заголовок и видимый текст страницы. |

Обычно вызывать их не нужно: аннотации приходят сами с сообщением. Инструменты нужны, если к теме
вернулись через несколько ходов или агент хочет перечитать страницу.

## Установка

Плагин ставится в профиль DSH как обычный бандл:

```powershell
dsh plugin --profile desktop add https://github.com/nachaloseo-blip/dsh-browser-annotate
```

или из локальной копии:

```powershell
git clone https://github.com/nachaloseo-blip/dsh-browser-annotate
dsh plugin --profile desktop add .\dsh-browser-annotate
```

После установки **перезапустите Harness**: состав профиля читается при старте процесса. Закрытия окна
недостаточно — приложение живёт в трее.

## Как это работает внутри

```
Client (React, слот conversation.composer.dock — только для опроса)
  └─ находит <webview> панели «Браузер»: webview[data-sidebar-browser-frame]
  └─ вставляет в страницу оверлей через executeJavaScript (idempotent, Shadow DOM)
  └─ раз в 0.7 с снимает snapshot: url, title, текст страницы, аннотации
  └─ POST /api/browser-annotate  { action: "sync" | "poll" | "clear" }

Host (index.js, без внешних импортов, кроме node:crypto)
  └─ exact Fetch route на общем канале /api — работает и по HTTP, и через IPC-транспорт Desktop
  └─ хранит последний snapshot и аннотации в памяти
  └─ на `agent/pre-step` прикладывает к шагу сообщение с аннотациями (source.kind = "user",
     чтобы лента отрисовала его обычным сообщением)
  └─ регистрирует инструменты browser_annotations и browser_page
```

Почему `source.kind: "user"`: DSH превращает сообщения с другим источником в служебные
«контекстные» записи и показывает их свёрнуто. Форма `user` — единственная, которая гарантированно
рисуется в ленте как обычное сообщение.

Оверлей живёт в Shadow DOM (`data-dsh-annotate-root`), поэтому CSS страницы его не ломает, а страница
не видит его разметку. Панелька и карточка комментария — тоже там.

## Ограничения

Честно о том, где не работает:

- **Только Desktop.** В Web-версии панель «Браузер» — это `<iframe>`, а не `<webview>`, и вставить в
  него оверлей нельзя (кросс-доменные ограничения).
- **Внутрь iframe и closed Shadow DOM** на самой странице выбор не проникает — только внешний носитель.
- **Скриншотов нет.** Агенту уходят DOM-факты: селектор, тег, текст. Картинку он не получает.
- **Right-click забирает контекстное меню сайта** внутри панели «Браузер». Нужен сайтовый — включите
  режим `Alt+A`, там работают только левые клики.
- **Аннотации живут в памяти хоста.** Перезапуск Harness — список пуст.
- **Ловушки фокуса в модальных окнах.** Плагин возвращает фокус в поле комментария, но если сайт
  блокирует ввод на уровне `inert`, поле может не принимать текст.
- **Не публичный API.** `executeJavaScript` и маркер `data-sidebar-browser-frame` — внутренняя механика
  панели «Браузер». Если DSH поменяет вёрстку, плагин перестанет видеть вкладку (панелька не
  появится), но приложение не сломается.

## Совместимость

Проверено на **DSH 0.2.1-rc.5** (Desktop, Windows). Плагин не объявляет `engines.dsh`, поэтому не
блокируется на других версиях, но и не гарантирует работу: механика слотов и `agent/pre-step` может
меняться между релизами.

## Разработка

Пакет — обычный ESM без сборки: правится `index.js` и `client.js`, переустановка не нужна (пакет
подключён ссылкой), но для применения изменений клиентской половины нужен перезапуск Harness.

Проверить синтаксис:

```powershell
node --check index.js
node --check client.js
```

Отлаживать удобно по логу сессии: аннотация приходит как `user/message` с текстом
«📎 К сообщению приложено…».
